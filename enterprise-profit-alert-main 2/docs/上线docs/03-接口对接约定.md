# 利润告警接口对接约定

日期：2026-11-27｜契约版本：v1 评审稿。以下 HTTP 接口均为拟新增，不代表现有能力。A 实现服务端，B 实现客户端；正式地址、身份及未确认字段在联调前填写，不能用示例冒充生产结果。

配套：[上线方案](01-最小上线方案.md)、[分工](02-AB分工.md)。

## 1. 公共约定

基础路径 `/internal/profit-alert/v1`，JSON UTF-8，仅内网 HTTPS。金额使用十进制定点字符串，拒绝 NaN/Infinity/缺失；不经浮点中转。时区 Asia/Shanghai。ID 使用字符串。所有示例为合成数据。

请求包含 `X-Request-Id` 和认证头；requestId 仅用于追踪，不是业务幂等键。使用现有 HMAC 规范：

```text
canonical = METHOD + "\n" + PATH + "\n" + timestamp + "\n" + nonce + "\n" + hex(SHA256(rawBody))
signature = hex(HMAC-SHA256(secret, canonical))
headers: X-Agent-Key / X-Agent-Timestamp / X-Agent-Nonce / X-Agent-Signature
```

签名针对实际发送字节，时间戳为 Unix 秒；PATH 不含查询串。v1 查询状态也用 POST，避免 unsigned 查询参数歧义。每次 HTTP 重试用新 nonce，但保持原业务幂等键。时间窗口采用服务配置，默认300秒。

现有 HMAC 使用共享密钥且 principal 不在签名串内：新增身份时必须按 principal 独立查密钥，阻止改头冒用，并把认证身份传入服务层。接口不接受客户端自报 agentKey 代替身份。内部 Dubbo 同时限制可信调用者。测试与正式身份/名单分开授权。

成功包装：`{"code":"OK","requestId":"...","data":{...}}`。失败包装：`{"code":"SOURCE_UNAVAILABLE","requestId":"...","message":"脱敏错误","retryable":true}`。不得用 HTTP 200 + 空列表掩盖来源失败。

| HTTP | code | 客户端处理 |
|---|---|---|
| 400 | INVALID_ARGUMENT | 修正输入，不自动重试 |
| 401/403 | UNAUTHENTICATED / FORBIDDEN | 停止，核对服务身份或名单 |
| 404 | NOT_FOUND | 不代表上游从未发送，按查单约束处理 |
| 409 | IDEMPOTENCY_CONFLICT / SOURCE_CHANGED | 停止，核对同槽位内容或重取整批数据 |
| 422 | SOURCE_INCOMPLETE / MAPPING_UNCONFIRMED | 禁止计算/发送，不补零 |
| 429/503/504 | RATE_LIMITED / SOURCE_UNAVAILABLE / UPSTREAM_TIMEOUT | 只读按预算退避；写动作先查单 |

契约版本、BI/MCP 上游版本（若提供）、适配器版本、代码发布版本和规则版本分别记录。上游无版本时明确 `sourceVersion:null`，通过获取时间、原始回执和摘要留证；摘要不等于来源版本，也不能证明跨页快照一致。

## 2. 接口目录

| 方法与路径 | 用途 | A 的下游 |
|---|---|---|
| POST /domestic/query | 国内逐页利润事实 | BI query |
| POST /international/daily | 国际完整单日回执 | 批准的 LiteLLM MCP |
| POST /deliveries | 为一个收件人提交卡片 | Notice 新增接口 |
| POST /deliveries/query | 按业务幂等键查投递状态 | Notice 权威账本 |
| POST /deliveries/readback | 查询并核验实际消息 | Notice + 飞书消息查询 |

以上路径均相对基础路径。dry-run 不调用 deliveries；test 是实际测试投递，production 是正式投递。

## 3. 国内查询

请求：

```json
{
  "startDate":"2026-11-01",
  "endDate":"2026-11-02",
  "customerTypes":["Customer","QuasiCustomer","Agent","CHANNEL"],
  "taxBasis":"INCLUDED",
  "indicatorView":"OPERATING",
  "page":{"number":1,"size":200},
  "queryId":null
}
```

日期含首尾，仅允许已结束自然日。源参数转换为 `cycle=Day, source=Detail, marketIndex=false`；枚举和值的可用性由 A 核对依赖后固定。BI endTime 严格小于，因此使用 endDate 次日00:00，而非当天23:59:59。

成功 data：

```json
{
  "queryId":"dq-synthetic-001",
  "success":true,
  "code":"GB:0000",
  "data":[{"timeStr":"2026-11-01","entCode":"SYNTHETIC-001","entName":"合成企业","smsIncome":"100.00","smsProfit":"20.00"}],
  "totalCount":1,
  "pageNumber":1,
  "pageSize":200,
  "meta":{"source":"BMP_BI","sourceVersion":null,"adapterVersion":"v1","consistency":"FROZEN_RECEIPT","fetchedAt":"2026-11-03T08:00:00+08:00","receiptSha256":"示例占位，真实返回64位hex"}
}
```

B 客户端拆外层包装后交给既有 query()，保留 totalCount/日期/身份/金额检查。A 必须明确以下映射并提供同输入对账：

| Python 字段/约束 | BI 适配要求 |
|---|---|
| timeStr | BI time 转上海日期 yyyy-MM-dd |
| entCode | 企业稳定编码，不能用展示名替代 |
| entName | 从公司主数据补齐；非零事实缺身份拒绝 |
| smsIncome | 对应含税 smsIncome，待同输入核对 |
| smsProfit | 候选为含税 smsOperateProfit，等价性核对前返回 MAPPING_UNCONFIRMED |
| customerTypes | BI QueryParams 未直接提供，A 经主数据落实同等范围，不静默忽略 |
| totalCount | 筛选后事实总数；不能先分页再筛选却沿用筛选前总数 |
| 排序/完整性 | 稳定唯一顺序，校验重复与缺页；总数不变不足以证明未漏行 |

分页最小落地：A 首次请求完整获取并校验源事实，冻结为受限日回执，返回 queryId；后续页带同一 queryId，从该回执分页，日期/筛选不得变化。源获取需稳定排序及完整性验证；若 BI 无法保证读取期间一致，A 要提供可验证的稳定读取窗口或源快照，不能伪称快照已存在。默认冻结回执保存7天供恢复，详细数据留存策略由公司确认；过期返回明确错误，B 必须重取全批，不能混合新旧页。

原 HTTP 路径 `/api/bmp/bi/customer-profit/query` 的上层转换不在当前五项目中；若无法取得源码，以授权同输入样本逐字段对账解除映射缺口。

    "end_time":"2026-11-02T23:59:59+08:00",
    "group_by":["enterprise_id","account_id","send_channel_id"],
    "truncated":false,
    "row_count":1,
    "rows":[{"enterprise_id":"synthetic-ent","enterprise_name":"合成企业","account_id":"synthetic-account","account_name":"合成账号","send_channel_id":"synthetic-channel","customer_total_amount":"100.00","channel_total_amount":"80.00"}]
  },
  "meta":{"sourceVersion":null,"adapterVersion":"v1","transport":"LITELLM_REMOTE_MCP","tool":"yuexin_mcp_gateway-billing_mcp__query_daily_stats_summary"}

A 使用公司身份调用已批准入口，初始化和 tools/list 验证后调用指定工具；保留上游其他来源字段和原始响应，不能为示例形状删减真实必需字段。B 将 receipt 保存为现有格式，执行原完整性/排除/金额校验。

A 以数据日及固定查询口径持久化来源查询尝试和成功回执，串行合并重复请求；每天首次正常查询一次，传输/包装/落盘失败最多追加两次。来源拒绝、截断、身份/金额错误不作为包装失败自动重试。B HTTP 断连后重取同日接口只能复用回执/继续原预算，不能启动新的三次预算。历史缺口由 B 逐日请求，只补输入，不补发旧告警。

## 5. 单收件人投递

请求：

```json
{
  "application":"enterprise-profit-alert",
  "dataDay":"2026-11-02",
  "mode":"test",
  "recipientId":"synthetic-company-user",
  "idempotencyKey":"epa-test-20261102-synthetic-user",
  "rulesetVersion":"合成规则版本",
  "rulesetSha256":"真实请求为64位hex",
  "inputSha256":"真实请求为64位hex",
  "cardSha256":"真实请求为64位hex",
  "card":{"schema":"2.0","body":{"elements":[]}}
}
```

示例卡片仅展示传参位置，实际必须使用现有构建器生成、经校验的完整卡片。recipientId 为 A 管理的公司稳定身份，A 解析到飞书标识并做名单授权；不允许任意收件人或客户端指定机器人凭据。联调前 A 提供测试/正式身份映射，B 不复制个人 CLI profile。

A 在 Notice 增加原始卡片投递方法，返回逐人消息 ID；agent-task 转发，不复制第二套权威投递账本。

### 幂等和事务

- 服务端按 `(application, dataDay, mode, recipientId)` 唯一约束。该槽位不含规则版本或卡片摘要，避免重算引发重复通知。
- idempotencyKey 是槽位的稳定别名，也必须唯一绑定槽位；同别名跨槽位或同槽位换别名都不产生新动作。
- 对规则摘要、输入摘要、卡片摘要及目标身份作内容绑定；同键/同槽位异内容返回409。人工更正通知另行设计，本期不提供绕过参数。
- B/A 对 cardSha256 的规范统一为 SHA256(UTF-8、对象键递归按 Unicode 码点排序、无多余空白、字符串保留 Unicode 的 JSON)。卡片中的数值仅允许整数；金额必须是字符串，避免跨语言浮点差异。提供包含中文/嵌套对象的联调向量验证一致。
- 写入 PREPARED 并提交事务，再以条件更新取得唯一发送权，提交 SUBMITTING 后调用飞书，随后单独事务保存响应。数据库事务不包住外部网络调用；多 agent-task 实例也不得重复发送。
- Notice 首期不增加新队列，持久记录后同步尝试单收件人发送。未知状态通过查询和人工核对处理，不设置自动重发后台循环。
- 飞书 uuid 去重仅在实际接口及有效期核实后辅助使用，不能替代持久账本。

### 返回及状态

新请求若已持久化返回202；已存在记录可返回200，均不代表业务成功。data 至少包含：

```json
{"deliveryId":"dl-synthetic-001","idempotencyKey":"epa-test-20261102-synthetic-user","state":"SENT","messageId":"synthetic-message","chatId":"synthetic-chat","readbackConfirmed":false}
```

| 状态 | 含义 | 允许动作 |
|---|---|---|
| PREPARED | 已存储，尚未开始外部调用 | 条件更新后尝试一次发送 |
| SUBMITTING | 已进入外部调用区间 | 查询，超时转 UNKNOWN；不可抢占重发 |
| SENT | 已取得消息 ID | 仅回读 |
| VERIFIED | 身份、目标和内容回读匹配 | 终态，重复请求只返回原结果 |
| REJECTED | 有明确证据未受理 | 修复后通过同键恢复，并重新校验权限/内容 |
| UNKNOWN | 外部可能发生但无法确认 | 查证或人工，禁止自动重发 |

重启后遇到遗留 SUBMITTING，不得因本地无 messageId 就判定未发送。UNKNOWN 确认未发生后的恢复由 A 提供受控操作单并留证；B 不自行删除记录。

## 6. 查单与回读

查单请求：`{"idempotencyKey":"epa-test-20261102-synthetic-user"}`。返回上述记录以及应用、数据日、模式、收件人、绑定摘要、更新时间和脱敏失败码。记录只对所属服务身份和授权范围可见。

回读请求：`{"deliveryId":"dl-synthetic-001"}`。服务端从账本取得 messageId，查询飞书，验证机器人、收件目标及内容。返回：

```json
{"deliveryId":"dl-synthetic-001","state":"VERIFIED","messageId":"synthetic-message","chatId":"synthetic-chat","recipientId":"synthetic-company-user","senderAppId":"synthetic-app","readbackConfirmed":true,"contentMatch":"EXACT","verifiedAt":"2026-11-03T08:01:00+08:00"}
```

原始卡片可精确规范化比较时返回 EXACT。飞书若返回渲染内容，则沿用现有受信业务标记校验，返回 RENDERED_MARKERS 并保留证据；不得因为存在 messageId 就返回 VERIFIED。读取失败保持 SENT；身份/目标/内容不符返回明确冲突并停止当日流程，不触发新发送。

写请求超时：B 先按原键查单。权威账本明确无记录时，可重放原提交，但服务端唯一约束仍必须防竞态；查单本身不可达时保持未知。404 不能证明飞书未发生，尤其不适用于已提交或账本恢复缺损情形。

建议客户端起始配置：连接5秒、只读响应120秒、发送响应30秒，均可配置；读取失败最多两次退避重试并服从来源全日预算。状态查询间隔5秒、每次运行最多等待5分钟，仍未完成保存 PENDING/UNKNOWN 并通知维护人员，不能当作成功或重发理由。实际阈值经测试确定。

## 7. B 的本地状态和完成条件

B 以 `(application,dataDay,mode)` 唯一保存运行，记录 stage、代码/规则/输入摘要、输出位置和错误；每个收件人保存 deliveryId 及已观察状态。正式日只允许一个活动执行，采用进程锁及本地唯一约束。

阶段：VALIDATING→FETCHING→CALCULATING→DELIVERING→VERIFYING→SUCCESS。只读失败记录 FAILED；未知发送记录 PENDING_RECONCILIATION。重新运行从已核验回执/投递记录恢复；已冻结并开始发送的输入不能被静默换成新取数。

- dry-run：产物完整，无发送尝试，保存原有 dry-run 回执。
- production 零告警：SUCCESS + NO_SEND_NO_BUSINESS_ALERT + message_count=0。
- production 有告警：所有应收件人的 VERIFIED 证据齐全，B 组装现有 receipt 格式，validate_output 通过后写 SUCCESS manifest。
- test：增加独立 receipt/manifest 模式校验，不复用 production 成功目录。零告警测试状态消息走独立测试状态用途与槽位，不能占用业务卡片槽位。

## 8. 必须联调的场景

| 场景 | 预期 |
|---|---|
| 正常国内/国际合成数据 | 与原计算同输入一致 |
| 缺页、重复页、日期/身份/金额错误 | 明确失败，不补零 |
| 源版本/快照变化 | 不拼接两次结果 |
| 测试身份访问正式名单 | 403，禁止回落 |
| 同槽位重复提交 | 同一 deliveryId，无新消息 |
| 同槽位不同卡片/规则/输入 | 409，不自动二次发送 |
| 两人成功后第三人失败 | 成功者不重发，逐人恢复 |
| 发送后断连、服务重启 | SUBMITTING/UNKNOWN 查证，不抢占重发 |
| 回读失败/不匹配 | 不判成功，不触发重新发送 |
| 跨日缺历史或规则不兼容 | 拒绝伪造续接，不自动补发历史通知 |
| 备份恢复或换机 | 恢复权威账本并核对未决消息后再启用发送 |

## 9. 联调前待落实项

A 填写：正式/测试基础地址、公司身份配置方式、Dubbo 与私有包版本、国内字段和客户类型映射、BI 稳定读取机制、MCP 权限及来源预算实现、Notice 新接口与回读证据、服务端发布版本。

B 填写：测试输入/预期产物位置、客户端版本、调度与磁盘配置、初始化历史与最后已通知日、测试名单配置、规则/机器人迁移版本、暂停和恢复操作。

以上是具体工程依赖，不要求重新提供整套业务需求；未解除的映射/权限缺口应阻塞对应真实动作，其他离线开发可以继续。
