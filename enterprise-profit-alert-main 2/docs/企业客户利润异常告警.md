## 当前规则 `2026-11-06.1`

- 不可变规则文件状态固定为 `APPROVED`，是否生效只由 `active.json` 的 `ACTIVE` 指针定义。
- 本版本明确利润异常告警与收入归属部门、经营看板 Base/卡片/仪表盘及其部门目标规则完全解耦；部门不参与来源、基线、阈值、告警筛选或卡片展示。
- 国际日回执只能通过 `https://flux-admin.yuexin.cn/mcp/` 的 `yuexin_mcp_gateway-billing_mcp__query_daily_stats_summary` 获取；旧 OAuth 网关 `106.14.207.126:8000` 明确禁止。
- 正式收件人在原金长春、寇誉博、李童晶基础上新增刘嘉玲；按企业邮箱在 `bmp-task-bot` 应用下实时解析。
- 国内客户类型按 BMP 最新客户利润表范围固定为 `Customer、QuasiCustomer、Agent、CHANNEL`，以 `QuasiCustomer` 替换已被该报表拒绝的 `Internet`；国内历史与当日明细必须使用同一范围重新查询。

- 当前数据日仍为完整自然日 T-1，但不再固定与 T-2 比较。
- 每家企业按日历类型独立建基线：普通周一至周日分别比较；法定节假日按节日类型比较；调休工作日单独比较。
- 基线取最近 6 至 8 个同类型历史样本的利润中位数；正常波动区间为 `基线 ± 3 × MAD`。
- 只有利润偏差额绝对值 `> 200元`、偏差率绝对值 `> 10%` 且超出正常波动区间时，才构成候选异常。
- 偏差率分母取 `max(abs(基线利润), 200元)`，避免基线接近 0 时放大比例；基线恰为 0 时仍不判定。
- 利润由正转负时单日立即告警；普通下降要求最近 3 个自然日中至少 2 日分别偏离各自基线。
- 单日普通下降进入观察，不推送为业务告警；利润上升只进入观察统计。
- 基线为 0、同类型样本少于 6 个、日历超出已确认覆盖期或来源缺失时不做业务判断，不补 0。
- 2026 年日历覆盖来自 `chinesecalendar 1.11.0` 的冻结提取；跨年运行前必须发布新的日历规则版本。
- 该版本激活前必须保证国内、国际当前来源、历史覆盖、回测、卡片和消息回读全部通过。没有业务人工标签前，只能验收技术行为和告警量，不能声称准确率已经提升。
- 零业务告警时生产任务不发送；一次性验收允许向唯一验收人寇誉博发送“零告警”卡片并完成回读，不改变生产策略。

## 原规则 `2026-08-27.2`

- 比较范围：国内、国际企业客户，比较完整自然日 T-1 与 T-2。
- 利润变化额：`昨日利润 - 对比利润`。
- 利润变化率：`利润变化额 / abs(对比利润) × 100%`。
- 同时满足 `abs(利润变化额) > 200元` 和 `abs(利润变化率) > 10%` 才告警；等于阈值不告警。
- 对比利润为 0 时变化率不可计算，保留审计但不进入业务告警。
- 当时的展示字段曾包含收入归属部门；该历史规则已废止，当前版本禁止查询、计算或展示该字段。
- 告警按“利润下降”和“利润上升”分区：下降使用红色，上升使用绿色。
- 每家告警企业展示截至昨日的近 15 个完整自然日利润折线图；缺日禁止补 0，趋势末两日必须与昨日利润、对比利润精确一致。

## 数据与任务边界

- 国内直接查询 BMP 客户利润明细，利润取源端 `smsProfit`。
- 客户类型由不可变规则 `sources.domestic.customer_types` 定义，国内查询脚本在访问源端前校验其与实际请求一致，并将类型范围写入源回执；业务响应 `success=false` 时直接保留源端错误并失败关闭。
- 生产 Runner 的国内历史和当日明细均使用 `scripts/query_enterprise_profit_alert_domestic.py`，仅请求 `/api/bmp/bi/customer-profit/query`；完整分页、金额缺失和非零企业身份均须校验，当日明细利润须与历史中的当日值逐企业一致。不得复用带部门或 CRM 补充查询的 `query_operating_board.py`。
- 国际直接查询 Pigeon `billing_mcp` 整体日明细，利润为原始客户金额减原始通道金额；禁止访问 OldLi。
- 连续日回执可由 `scripts/fetch_enterprise_profit_alert_pigeon.py` 获取：读取现有 LiteLLM 凭据，在指定网关完成初始化、工具发现和准确工具调用，逐日原子保存回执及查询次数；重跑时先验证当前运行目录内已保存的回执，避免重复查询。
- 收入归属部门不是本任务依赖，不查询、不计算、不展示。
- 本任务不读取经营看板 Base、卡片、仪表盘或发布状态；这些展示层失败不得阻塞本任务。
- 任一权威来源、分页、身份、映射或回读门禁失败时停止推送，不用旧数据降级。
- 前序历史缺日时，从最近连续成功历史的下一日开始逐日查询权威 Pigeon 回执，并在当天正式 Runner 中一次性合并；回执日期必须连续、无重复且完整覆盖至当前数据日。历史恢复过程不补发旧日告警，只对当前数据日执行生产投递。
- 客户范围变更可通过唯一 Runner 的 `--dry-run --candidate-rules` 完成候选数据验证；候选只允许该范围变更且禁止生产发送。正式发送须先由 `scripts/activate_enterprise_profit_alert_rules.py` 激活新规则，再运行生产入口。

## DeerFlow Agent

- Agent 名称：`enterprise-profit-alert`；只绑定 `enterprise-profit-alert-preview` Skill。
- Skill 通过 `allowed-tools` 仅暴露 `enterprise_profit_alert_run_enterprise_profit_alert_preview`，不允许通用 Bash、文件写入或其他 MCP 工具。
- DeerFlow 入口固定为严格 `dry-run`：只构建并校验 history、alert、Card 2.0、manifest 和 dry-run receipt，不调用飞书发送脚本。
- 可执行日期必须登记在 `config/enterprise-profit-alert-agent/preview-snapshots.json`，并同时通过日期覆盖和 SHA-256 校验；未登记日期或哈希漂移时失败关闭，不切换日期、不使用旧结果。
- dry-run 成功必须同时满足 `execution_mode=dry-run`、`delivery_status=DRY_RUN_NOT_SENT`、`send_attempted=false` 和 `message_count=0`。
- 当前 DeerFlow Agent 不承担生产发送授权；正式推送仍沿用原生产 Runner 的身份、幂等和消息回读门禁。
