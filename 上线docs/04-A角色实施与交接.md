## 配置和构建

agent-task 默认构建可运行离线测试；部署包使用 Maven `-Pprofit-dubbo package` 引入通用Dubbo客户端。采用泛化调用以避免私有API模型编译耦合，提供方接口类名和参数签名仍按03契约绑定。Dubbo及私有服务版本必须在公司环境联调固定；该方式不表示已验证服务兼容。

配置采用 Spring 属性，以下都是需要团队填入的配置项，不含真实密钥：

- `agent.task.principal-secrets.<principal>`：每个调用身份独立密钥；新接口禁止使用共享后备密钥。
- `agent.task.agent-principals`：加入已授权利润调用身份。
- `profit.identities.<principal>.mode`：test 或 production。
- `profit.recipients.<mode>.<recipientId>`：对应飞书接收ID。
- `profit.notice.app`：公司已配置的 NoticeApp。
- `profit.notice.receive-id-type`：user_id 或 open_id。
- `profit.notice.url`：受保护内网提供方 Dubbo 直连地址；生产网络必须限制调用者。
- `profit.source.dubbo-registry`、`dubbo-group`、`dubbo-version`：BI注册发现。
- `profit.source.customer-ids`、`enterprise-names`：经主数据核对的完整范围及名称映射快照。
- `profit.source.mapping-confirmed`、`stable-read-confirmed`：默认false，只有实际完成映射及源读取一致性核查后才启用。
- `profit.source.mcp-url`、`mcp-token`：批准MCP入口及公司凭据。

国内范围暂以服务端配置快照适配。必须指定主数据快照来源、核对日期及更新责任，不能让过期名单长期代替动态主数据。未确认映射直接返回 MAPPING_UNCONFIRMED；空客户范围不会回落到全量。

agent-task 的V2来源表随Liquibase master执行。Notice新增SQL位于其service资源db目录，部署前由公司数据库迁移流程执行，并配置Spring数据源及事务管理器。详见notice目录交付说明。
