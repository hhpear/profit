# A/B 两人分工与交接

日期：2026-11-27｜评审稿 v1.0。A=Java 服务及接口负责人，B=Python 告警及部署负责人；实际人员待团队指定。

依据：[最小上线方案](01-最小上线方案.md)、[接口对接约定](03-接口对接约定.md)。第一期不接 Runtime。

## 1. 工作归属

| 工作 | A | B | 完成证据 |
|---|---|---|---|
| 国内数据 | BI 调用、客户范围/金额/名称/日期映射、分页完整性和来源证明 | HTTP 客户端、保留源校验、计算对账 | 映射表、同输入对账结果 |
| 国际数据 | 公司 LiteLLM MCP 身份、工具检查、原始日回执、服务端尝试预算 | 连续补日、落盘校验、历史合并 | 连续多日回执及异常样例 |
| 飞书投递 | Notice 原始卡片接口、持久化幂等、消息 ID、回读、权限 | 保留卡片内容/身份校验、调用与恢复、组装回执 | 正常/部分成功/UNKNOWN 演练 |
| agent-task | Controller、Dubbo/MCP 客户端、认证授权、错误码、接口日志 | 对接 HTTP、超时与重试分类 | 契约测试与端到端记录 |
| 告警算法 | 提供源字段解释 | 保留算法、规则版本、产物校验；处理测试模式 | 核心测试、差异清单 |
| 服务端部署 | Java 构建、服务注册、内部依赖、数据库迁移、密钥 | 协调连通性并记录依赖版本 | 测试/生产服务版本清单 |
| Python 部署 | 配合网络和权限 | 镜像、唯一调度、单机锁、SQLite/磁盘、超时、监控、备份 | 部署说明与恢复演练 |
| 首次历史与切换 | 查询旧投递和新投递账本 | 导入合法历史、核对旧状态、关闭旧调度、启用新调度 | 首个数据日与最后已通知日 |
| 试运行 | 查接口、取数和投递差异 | 每日运行记录、结果比对与汇总 | 连续一周试运行报告 |

算法/范围变更、正式收件人范围和正式切换由既有业务负责人确认；A/B 负责准备可审阅证据，不代替业务决策。服务器和服务权限由对应管理员配合，不假设已获授权。

## 2. 可并行步骤与交接门槛

### 阶段一：契约和离线开发

- A 输出国内字段映射、五个接口的合成样例、错误及状态语义，确认内部依赖版本。
- B 基于约定样例实现客户端、单入口和持久化恢复，先用模拟客户端跑通完整流程。
- 双方共同核对金额字符串、日期边界、模式隔离、幂等键和 UNKNOWN 行为。
- 门槛：契约示例可解析，双方对同键异内容/部分成功/回读失败预期一致。

### 阶段二：测试环境联调

- A 交付测试基础地址、独立服务身份申请方式、Dubbo/MCP 可达性和公司测试机器人配置。
- B 交付固定输入、预期输出和客户端版本；客户真实数据只在授权位置共享。
- 先取数再 dry-run，再向确认的测试名单发送；生产名单与测试名单不能互相回落。
- 门槛：同输入结果一致，错误场景不补零，实际发送有逐人 ID 和回读证据。

### 阶段三：试运行与上线

- B 主持每日检查并记录数据日、规则/代码版本、异常数和差异；A 排查接口/来源/投递问题。
- 一周试运行按既有交接要求进行，具体起止日和实质故障是否重计由技术及业务共同确认。
- A 完成 Java 正式部署与数据库迁移；B 完成历史/投递状态迁移和调度切换。切换前两人核对 UNKNOWN 消息。
- 门槛：技术测试、试运行、恢复演练和技术/业务切换确认齐全。

## 3. 各自交付清单

A：Java 修改及正式仓库提交标识；接口样例和联调地址；国内映射表；公司身份/权限配置说明（不含密钥）；Notice 数据库迁移；逐人投递与查单记录；Java 部署/回退说明。

B：Python 修改及正式仓库提交标识；依赖锁定及镜像标识；配置清单；调度/锁/超时/漏跑配置；历史初始化记录；SQLite 与产物备份恢复说明；核心和恢复测试结果；一周试运行记录；停旧启新及回退操作单。

双方：契约版本、已知问题、未解决差异、首个正式数据日、维护与备用联系人。排期和联系人不在本稿中虚构。

## 4. 故障归属与恢复

| 现象 | 首查 | 处理约束 |
|---|---|---|
| 漏跑、卡住、磁盘、Python 校验失败 | B | 先保留现场，检查阶段和输入，不跳过校验 |
| 401/403、Dubbo/BI/MCP 错误 | A | 修复公司权限或来源；不切个人身份 |
| 金额/名单差异 | A 查映射，B 查计算与规则 | 同输入复现，业务确认口径 |
| 部分发送、UNKNOWN、回读不符 | A 查权威投递，B 暂停本日自动恢复 | 查证后只恢复确认未发送的人 |
| 错发、重复或数据错误 | A/B 立即暂停投递 | 是否更正通知及恢复由业务确认 |

上线后的响应时段、响应时限和备用通知通道，在切换记录中填写并演练，不把业务飞书通道作为唯一故障通知方式。
