## 入口与运行

在项目根目录执行：

```sh
python3 -m scripts.demo_profit_alert_b1 --output-dir /tmp/profit-alert-b1-demo
python3 -m unittest scripts.test_profit_alert_b1 scripts.test_enterprise_profit_alert scripts.test_enterprise_profit_alert_domestic
python3 scripts/validate_enterprise_profit_alert_governance.py
```

演示使用固定合成数据日 2026-11-26。dry-run、test、production 均走同一编排，后两种模式使用模拟服务；不产生真实消息。演示目录包含 SQLite、按模式和数据日隔离的产物、来源回执、冻结输入、逐人证据及汇总。重新执行演示会新建内存模拟权威账本，因此跨进程重放会因本地已提交而权威记录丢失停止；这属于预期保护。需要重新演示时使用新的输出目录，不要删除正式账本模拟恢复。

真实只读取数入口：

```sh
python3 -m scripts.profit_alert_b1 --state-dir /持久目录/profit-alert --previous-history /授权目录/history.json --mode dry-run
```

由运行环境注入 PROFIT_API_URL、PROFIT_API_KEY、PROFIT_API_SECRET。地址要求 HTTPS；不记录密钥。数据日默认北京时间昨日，可用 --data-day 显式指定已结束日期。当前 B1 对真实 HTTP 的 test/production 投递直接拒绝，待 B2 完成公司规则版本、名单授权与回读联调后接通；模拟服务可以覆盖全部三种模式。

## 状态与恢复

runs 以数据日、模式唯一记录阶段和绑定摘要，metadata 保存发布标识、规则版本/摘要、输入摘要及输出目录。deliveries 保存逐人提交意图及观察到的权威证据。发送前提交本地 SUBMITTING 意图；写请求断连后停止，本次运行记 PENDING_RECONCILIATION。重跑先查服务端账本；已发送仅回读，不重新发送。本地存在意图而权威账本 404 时停止。

SUBMITTING 以5秒间隔最多等待5分钟；UNKNOWN 不自动重发；PREPARED 通过原键推进。REJECTED 保留待核对，不自行修复权限或删除槽位。回读必须核对 deliveryId、收件人、机器人、内容匹配及消息 ID。

来源输入冻结后重跑复用，计算后先以 dry-run 门禁校验产物和源摘要，再执行任何投递。所有应收件人核验通过后写 SUCCESS manifest 和本地 SUCCESS。文件原子写入；数据库与文件不声称具备跨介质事务，重启重新校验。
